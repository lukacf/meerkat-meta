The Rust crate `meerkat-meta` is the primary interface for Meta. All other interfaces (JSON-RPC, SDKs, console) are built on top of it.

## Installation

```toml Cargo.toml
[dependencies]
meerkat-meta = "0.9.0"
tokio = { version = "1", features = ["full"] }
serde_json = "1"
```

## Quick start

Host-supplied modules are optional. This runnable baseline starts no module
processes; add module declarations only for executables or MCP transports your
host actually supplies.

```rust
use meerkat_meta::{start_meta_runtime, DiscoverySpec, MetaConfig};
use std::time::Duration;

let config = MetaConfig {
    modules: vec![],
    discovery: DiscoverySpec {
        namespace: "my-app".into(),
        modules: vec![],
    },
    pre_spawn: vec![],
};

let runtime = start_meta_runtime(config, vec![], Duration::from_secs(30))?;
```

## Core types

### MetaConfig

Top-level configuration for the module runtime.

```rust
struct MetaConfig {
    modules: Vec<ModuleConfig>,
    discovery: DiscoverySpec,
    pre_spawn: Vec<PreSpawnData>,
}
```

### ModuleConfig

Configuration for a single module.

```rust
struct ModuleConfig {
    id: String,
    command: String,
    args: Vec<String>,
    restart_policy: RestartPolicy,
}
```

### EventEnvelope

Timestamped event wrapper.

```rust
struct EventEnvelope<T> {
    event_id: String,
    source: String,
    timestamp_ms: u64,
    event: T,
}
```

### UnifiedEvent

Agent or module event discriminator.

```rust
enum UnifiedEvent {
    Agent {
        agent_id: String,
        event_type: String,
        payload: Option<Value>,
    },
    Module(ModuleEvent),
}

struct ModuleEvent {
    module: String,
    event_type: String,
    payload: Value,
}
```

## Runtime functions

### `start_meta_runtime`

Bootstrap a module-only runtime:

```rust
fn start_meta_runtime(
    config: MetaConfig,
    agent_events: Vec<EventEnvelope<UnifiedEvent>>,
    timeout: Duration,
) -> Result<MetaRuntimeHandle, MetaRuntimeError>
```

### `start_meta_runtime_with_options`

Bootstrap with additional options:

```rust
fn start_meta_runtime_with_options(
    config: MetaConfig,
    agent_events: Vec<EventEnvelope<UnifiedEvent>>,
    timeout: Duration,
    options: RuntimeOptions,
) -> Result<MetaRuntimeHandle, MetaRuntimeError>
```

### `UnifiedRuntime::builder`

Builder for the combined mob + module runtime:

```rust
UnifiedRuntime::builder()
    .mob_spec(spec)
    .module_config(config)
    .timeout(duration)
    .build()
    .await?
```

For identity-first runtimes with a roster provider, the Rust builder can enable
identity-scoped agent memory injection. Open the SQLite authority explicitly
and pass it through the provider seam:

```rust
use std::sync::Arc;
use meerkat_meta::{AgentMemoryConfig, SqliteAgentMemoryStore, UnifiedRuntime};

let memory = Arc::new(SqliteAgentMemoryStore::open(".meta/state/agent-memory")?);

let runtime = UnifiedRuntime::builder()
    .definition_path("config/mob.toml")
    .persistent_state(".meta/state")
    .roster_provider(roster_provider)
    .agent_memory(memory, AgentMemoryConfig::default())
    .build()
    .await?;
```

The SQLite provider stores one database per realm. When a realm is first
accessed and its SQLite connection is opened, it imports that realm's legacy
markdown files from the same agent-memory directory. Markdown is not a live
provider. To supply another storage or retrieval authority, pass any
`Arc<dyn AgentMemoryProvider>` with `.agent_memory(provider, config)`.

Rust callers can write, read, and delete durable records through the unified
runtime:

```rust
use meerkat_meta::{AgentMemoryRecallRequest, AgentMemorySelection, NewAgentMemory};

let record = runtime
    .remember_agent_memory(
        "default",
        &identity,
        NewAgentMemory {
            title: "Deployment preference".into(),
            body: "Use the staging realm before production deploys.".into(),
            tags: vec!["deploy".into()],
        },
    )
    .await?;

let records = runtime
    .recall_agent_memory(AgentMemoryRecallRequest {
        identity: identity.clone(),
        realm: "default".into(),
        selection: AgentMemorySelection::Contextual,
        query_text: Some("What should I check before deploying?".into()),
        query_terms: vec!["deploy".into()],
        max_entries: 4,
    })
    .await?;

if let Some(record) = records.first() {
    runtime
        .forget_agent_memory("default", &identity, &record.memory_id)
        .await?;
}
```

## Operational subsystem functions

### Decisions

```rust
fn validate_bigquery_naming(naming: &BigQueryNaming) -> Result<(), DecisionPolicyError>
fn load_trusted_meta_modules_from_toml(toml: &str) -> Result<Vec<ModuleConfig>, DecisionPolicyError>
fn enforce_console_route_access(auth: &AuthPolicy, console: &ConsolePolicy, req: &ConsoleAccessRequest) -> Result<(), DecisionPolicyError>
fn validate_runtime_ops_policy(policy: &RuntimeOpsPolicy) -> Result<(), DecisionPolicyError>
fn validate_trusted_oidc_runtime_config(config: &TrustedOidcRuntimeConfig) -> Result<(), DecisionPolicyError>
fn build_runtime_decision_state(input: RuntimeDecisionInputs) -> Result<RuntimeDecisionState, DecisionRuntimeError>
impl RuntimeDecisionState {
    // Explicit opt-out: a console that trusts no identity provider.
    fn local_console(console: ConsolePolicy, bigquery: Option<BigQueryNaming>) -> Self
    // Trusted module set for a local_console state (starts empty).
    fn with_modules(self, modules: Vec<ModuleConfig>) -> Self
}
```

`build_runtime_decision_state` is the validating constructor; it checks the
trusted OIDC snapshot only when `console.require_app_auth` is `true`.
`RuntimeDecisionState::local_console` is the explicit opt-out for local or
host-protected consoles; at serve time the runtime reads `console`, the
session-store naming and `modules`, and a host with trusted modules adds them
with `.with_modules(...)`. The default stays fail-closed: `ConsolePolicy::default()`
requires app auth, and a state that trusts no key refuses every request. See
[Decisions](/reference/decisions#runtime-decision-state) for every check and
when it runs.

`gateway_composition` also exports the HTTP exposure vocabulary both binaries
use: `GatewaySurface` (`RpcGateway` | `MetaGateway`, `Display` is the binary
name), `ConsoleAuthPosture::of(&decisions)` (`Open` | `ClosedToEveryCaller` |
`Enforced`, the one classifier behind the bind gate and the non-loopback
warning), `HttpBindPolicy`, `validate_http_bind_policy(surface, listen, policy)`,
`warn_on_non_loopback_bind(surface, bound, &decisions)`, and the typed
`HttpExposureParseError` behind `parse_http_listen_addr`,
`parse_http_public_base_url` and `parse_http_listen_arg`. The error enums
(`HttpBindPolicyError`, `HttpExposureParseError`, `GatewayHostConfigError`,
`HostConfigTableInMobToml`) are `#[non_exhaustive]`.

### Authentication

```rust
fn inspect_jwt_header(token: &str) -> Result<JwtHeaderView, JwtValidationError>
fn validate_jwt_locally(token: &str, config: &JwtValidationConfig) -> Result<ValidatedJwt, JwtValidationError>
fn parse_oidc_discovery_json(json: &str) -> Result<OidcDiscoveryDocument, OidcContractError>
fn parse_jwks_json(json: &str) -> Result<JwksDocument, OidcContractError>
```

### Governance

```rust
fn validate_governance_state(file_name: &str, content: &str) -> Result<(), GovernanceValidationError>
fn validate_traceability_statuses(markdown: &str) -> Result<(), GovernanceValidationError>
```

The first function receives a diagnostic file label and document contents, not
a state value or a file to read. The second accepts a Markdown table or YAML
traceability document, including evidence for statuses that require it; it does
not accept an array of status names. See [Governance](/reference/governance)
for complete examples and the validators' limits.

## HTTP routers

Build Axum routers for serving the console and interactions:

```rust
// Decision state. Explicit opt-out for a local console that trusts no
// identity provider; ConsolePolicy::default() would require app auth and,
// with no trusted key, refuse every request.
let decisions = RuntimeDecisionState::local_console(
    ConsolePolicy { require_app_auth: false, ..ConsolePolicy::default() },
    None,
);
// Authenticated console: build_runtime_decision_state(RuntimeDecisionInputs { .. })?

// Console frontend (HTML + JS + CSS)
let frontend: Router = console_frontend_router();

// Console JSON API, JSON-RPC, timeline SSE, multipart upload/send, and blobs
let json_api_without_runtime: Router = console_json_router(decisions.clone());
let json_api_with_runtime: Router =
    console_json_router_with_runtime(decisions, mob_runtime, None, None);
```

Binding is separate from routing. `GatewayHttpBinding::bind_loopback()` is
the default posture (loopback, ephemeral port) and
`GatewayHttpBinding::bind(addr)` takes any `SocketAddr`; `http_base_url()`
returns the same-host form, mapping wildcard binds to loopback of the same
family: `0.0.0.0:PORT` becomes `http://127.0.0.1:PORT`, and `[::]:PORT`
becomes `http://[::1]:PORT`. Concrete bound addresses and the bound port are
preserved. `with_advertised_base_url(..)` carries a proxy-facing base for
your init reply.

Before binding, validate the requested `addr: SocketAddr` against your launch's
`allow_remote` acknowledgement and decision state:

```rust
use meerkat_meta::gateway_composition::{
    validate_http_bind_policy, GatewaySurface, HttpBindPolicy,
};

validate_http_bind_policy(
    GatewaySurface::RpcGateway,
    addr,
    HttpBindPolicy::for_gateway(allow_remote, &decisions),
)?;
```

`GatewaySurface` is the closed gateway diagnostic enum, not an arbitrary
host name; use `GatewaySurface::MetaGateway` instead when representing that surface.
The check applies the gateways' fail-closed rule: non-loopback needs enforced
console auth or the `allow_remote` acknowledgement. After binding, call
`warn_on_non_loopback_bind(surface, bound, &decisions)` for the gateways'
WARN line. These helpers and `GatewayHttpBinding` live in
`meerkat_meta::gateway_composition`. See [Deployment](/guides/deployment).
